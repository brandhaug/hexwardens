# Adopt GLB Mesh Assets from Poly Pizza

The Board's procedural primitive geometry (cylinders, capsules, cones, dodecahedra) is being incrementally replaced by curated GLB mesh assets sourced from Poly Pizza (CC0 / CC-BY 4.0 low-poly catalogue). ADR-0004 anticipated this — it kept the procedural geometry as a first cut and noted that "GLB assets and richer terrain texturing [are] able to replace registry entries later." This ADR records how that replacement is structured.

GLBs are **committed to the repo** at `apps/web/public/models/<category>/<name>.glb`, served as static assets and loaded with drei's `useGLTF`. The Worker runtime never reaches Poly Pizza's CDN; Poly Pizza is a curation-time tool for contributors. This preserves the offline `/game` invariant in `apps/web/CLAUDE.md`, keeps builds reproducible, and avoids a runtime dependency on a hobbyist CDN. The cost is bounded repo growth (~100 KB per asset, ~60 entities at full migration).

Procedural rendering remains a **permanent first-class option**, not a transitional state. The Visual Registry is a discriminated union — each entry is either `{ kind: 'mesh', path, tintMaterial?, attribution? }` or `{ kind: 'procedural', render }`. Each entity transitions independently when a good GLB candidate is found; entities with no good Poly Pizza match (or whose silhouette is better expressed procedurally) stay procedural forever. This keeps the migration shippable in small PRs, gives the type system honest content, and avoids forcing a mediocre GLB on niche entities like the Tidebreaker. GLB load failures surface visibly through the Suspense error boundary — no silent fallback to procedural, because that masks regressions.

CC-BY 3.0 and CC-BY 4.0 models are accepted alongside CC0 to preserve the candidate pool — Poly Pizza hosts substantial catalogues under each (notably Poly by Google's CC-BY 3.0 set), and the attribution requirements are equivalent. Attribution lives in the registry entry itself, copied verbatim from Poly Pizza's `Attribution` field on the source model (which is authoritative and already in the form the artist and Poly Pizza expect). A Vitest test asserts that every non-CC0 entry has a non-empty `attribution` string. The string is surfaced in-app via a `/credits` route generated from the registry. The alternative — CC0-only — would have removed the compliance surface but shrunk the candidate pool meaningfully across 60+ entities. The attribution mechanism is a one-off cost that disappears into the registry once built and benefits any future hand-modeled or AI-generated assets too.

The registry is **split per category** (`village-visual-registry.ts`, `unit-visual-registry.ts`, `hero-visual-registry.ts`, `building-visual-registry.ts`, `resource-visual-registry.ts`, plus the existing `board-visual-registry.ts` which holds the colour tokens and the `getVisualEntry` dispatcher). Each file is `Record<EntityKey, VisualRegistryEntry>`, so adding a new entity to `@hexwardens/game-logic/domains/*` without registering its visual is a compile error — the same exhaustiveness pattern as today's `tribeToMaterialColor`. Splitting per category keeps PRs small, avoids monolithic-file conflicts during the rolling migration, and keeps the no-barrel-files rule intact (the dispatcher is a function with logic, not a re-export).

Considered alternatives: (a) **runtime CDN fetch** of Poly Pizza GLBs — rejected because it would break offline `/game`, make builds non-reproducible, and create a runtime dependency on a hobbyist CDN; (b) **transitional procedural** with a hard switch to mesh-only at the end of migration — rejected because it forces all 60+ entities to ship together and makes niche entities adopt mediocre GLBs; (c) **CC0-only** — rejected because the attribution mechanism is a small one-off cost that more than pays for itself across the catalogue; (d) **single-file Visual Registry** — rejected for merge-conflict surface during a multi-PR migration; (e) **AI-generated 3D pipeline** (Meshy / Tripo) replacing the deleted `tools/sprites/` — deferred, not rejected: re-evaluate once the Poly Pizza catalogue's coverage gaps are concrete.
