## Failure cases to verify before implementation

- Missing or malformed stage, path traversal, overlong Worker names, accidental production alias, and account confirmation mismatch must fail before invoking Alchemy.
- Production resource names and existing Durable Object class names must remain stable; preview resources must differ by PR.
- Origin validation must reject credentials, wildcards, paths, query strings, fragments, non-HTTPS production origins, empty lists, and entries containing only whitespace.
- Generated configurations must detect manual drift; web, game-server and migrations must use the same local database identity and persist root.
- A migration appended after an existing schema must run once without destroying player data.
- Failed or cancelled CI jobs must fail the aggregate; cleanup must not be cancelled by another deployment; PR code must never receive production credentials.
- Scanner failure must fail the job; PR exceptions must not suppress findings before merge.
- Backup ciphertext must authenticate before restore; stale or incomplete backups must fail freshness; restore must refuse production and require an exact isolated target.

## Implemented changes

- Migrated Alchemy to beta.79's `Cloudflare.Website.Vite`, `Cloudflare.D1.Database`, `Cloudflare.DurableObject`, `env` bindings and `migrations: { dir }`. Preserved stack, logical IDs, production names and the three DO class names. Production D1 uses `RemovalPolicy.retain`; the wrapper refuses production destruction.
- Added canonical `infra/bindings.ts`, generated Wrangler configs for game-server, web and database operations, and a semantic drift check that permits formatter-only changes. Compatibility date `2026-09-26` matches the installed workerd release rather than requesting a newer runtime than local tooling supports.
- Added stage-isolated names and rate-limit namespace IDs. Native `WEB_RATE_LIMITER` permits 60 requests per minute; `GAME_RATE_LIMITER` permits 120. These are per-location coarse limits, not hard global quotas. Application enforcement belongs to the security slice.
- Added exact account/stage deploy and destroy guards, strict HTTPS origin parsing, and public `VITE_GAME_SERVER_URL` derivation from the same stage URL as `GAME_SERVER_URL`. The native build refuses Node shim flags.
- Migrated the web shim and game-server D1 fixture to native Miniflare 5 `workers[].config.manifest/env` and shared `resourcePersistencePath`. The web shim now applies pending migrations atomically with Wrangler ledger entries. A legacy schema without a ledger adopts only the initial baseline after comparing every table/index definition, preserving existing rows.
- Pinned GitHub Actions to current immutable release commits, set read-only default permissions, bounded job timeouts, retained existing CI job names and added a fail-closed `CI gate`. Setup verifies the Vite+ 1.0.0 bootstrap checksum and uses frozen pnpm installation. CI also checks generated infrastructure and the shared-D1 probe.
- Added protected production deployment with exact default-branch SHA and CI/Audit verification, HTTPS health probes, isolated approved same-repository previews, and close cleanup from default-branch code. Stage mutations are serialized without cancellation. Deployment workflows remain opt-in through repository variables.
- Added Gitleaks history scanning with built-in rules and Trivy lockfile scanning using only trusted default-branch exceptions. Scanner integration fixtures verify severity, fixed findings, expiry, package/version/path scope, secret detection and redacted output. No vulnerability exceptions were introduced.
- Added encrypted D1 export, authenticated completion records, independent freshness verification and local-only restore drills with integrity/foreign-key checks. No remote restore interface exists. Backup retention is an external private-bucket lifecycle policy, avoiding broad cloud deletion privileges.
- Rewrote deployment/recovery instructions and added infrastructure security guidance, including protected environments, workflow review, secret scope, account isolation, migration ordering and DO persistence compatibility.

## Deliberate exclusions and differences from the starter

| Starter feature                                       | Decision and reason                                                                                                                                                                                    |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Billing/webhook/email/export queues and schedules     | Excluded. Hexwardens has no corresponding domain, producer, consumer or provider credential need.                                                                                                      |
| SaaS seed workspace and preview demo credentials      | Excluded. A game preview starts with an empty isolated D1 and never copies player credentials.                                                                                                         |
| Billing and organization retention/recovery operators | Excluded. Their tables and policy approvals do not exist here. Backups protect the game's D1 schema instead.                                                                                           |
| Sentry backup monitor pings                           | Excluded. Hexwardens uses Workers wide events and has no Sentry deployment; failed-run notifications and external missed-run monitoring are documented prerequisites.                                  |
| Unattended production destroy                         | Rejected. Production teardown is disabled, even with a matching target confirmation. Preview destroy remains guarded.                                                                                  |
| Remote backup restore and automatic pruning           | Replaced with isolated local restore drills and storage lifecycle retention. A production restore needs a separately reviewed account/database target and maintenance window.                          |
| Starter's older Vite+ and action pins                 | Updated against official release metadata rather than copied unchanged.                                                                                                                                |
| Separate `@cloudflare/vite-plugin`                    | Not installed. Official Alchemy beta.79 documentation explicitly says it conflicts with Alchemy's native runtime plugin.                                                                               |
| Local D1 shim removal                                 | Not removed. Hexwardens' separate web and game-server dev processes require shared local D1, and Vitest runs in Node. Native Alchemy remains the deployment integration.                               |
| Automatic remote D1 migration baselining              | Not copied. Current Alchemy adopts existing migration bookkeeping; blanket table-existence baselining could conceal a partially applied game schema. Local legacy adoption compares exact definitions. |
| Smart placement on multiplayer                        | Not copied. Durable Objects already own match placement; moving the public WebSocket ingress near D1 is not justified by measured latency.                                                             |
| Preview GitHub deployment comments/status API         | URLs are written to the job summary; no PR comments or notification messages are posted.                                                                                                               |
