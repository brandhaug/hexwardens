## Domain differences to preserve

The starter's SaaS features are not tooling upgrades. Workspace billing, seat entitlements, organization membership, workspace exports, onboarding, outbound webhooks, tenant SSO, MCP OAuth, AI assistants and queued digest email have no current game requirement. Their operational patterns are candidates only where Hexwardens has a corresponding resource or workflow.

The starter deliberately omits realtime transport, Durable Objects and PWA behavior without a product need. Hexwardens already needs all three. Keep multiplayer hibernation, per-match state, offline play and saved-match synchronization.

Do not copy the starter's single-theme visual rules, typography, Tailwind allowlists, content, or localization catalog. Hexwardens owns its design tokens and game vocabulary. Generic accessibility and type-safety rules still apply.

Passkeys, magic links, email codes, social login and account lifecycle features change the product's authentication options. Compare security of the existing login paths first; adding every optional provider is not required to port setup improvements.

Database baseline bookkeeping must not silently mark unapplied Hexwardens migrations as applied. Evaluate it against the existing migration history before recommending any port.

## Validation and delivery

Each implementation slice must record commands and observed results, a fixed review base/head, and any unresolved external blocker. The integrated checkout must pass lint, format, typecheck, web/game-logic tests, production build and relevant E2E paths. Dependency metadata must be rechecked against the final lockfile.

Repository workflows do not prove that GitHub rulesets, environment approvals or Cloudflare credentials are configured. Inspect available read-only settings and report unverified activation separately. Do not deploy, destroy resources, rotate credentials, or merge pull requests as part of this audit.

The implementation slices are integrated. Strict lint, compiler and native Effect checks, application tests, production and Storybook builds, and the zero-debt Fallow gate pass. All 28 browser cases pass locally without retries. Fresh independent Standards and Spec reviews found no actionable issues. See [integrated validation](integrated-validation.md) for the reviewed revisions, test evidence and CI status. Engine investigations are recorded in [bevy-ts assessment](bevy-ts-assessment.md) and [Effect Machine assessment](effect-machine-assessment.md), with isolated probe evidence. Neither library was added to production dependencies.
